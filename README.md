## ✨ 核心特性

### 1. 🔍 一键全景扫描与多源状态精准识别
- **全依赖自动穿透**：智能解析当前 Profile 的 `package.json`，自动区分第三方扩展，自动跳过官方内置的基础包（`@deepseek-ai/*`）。
- **全源格式兼容**：
  - **npm 版本依赖**（`^1.2.3`、`~0.1.6`、精确版本）：优先查询 npm 官方镜像源，并支持 npmmirror 智能回退。
  - **GitHub 远程引用**（`github:owner/repo#tag`）：精准比对 GitHub Releases 最新稳定版本；未写 `#ref` 时用已装版本与最新 tag 比较，落后即判「有更新」，版本号无法排序时才判「跟踪分支」（v0.4.1 起）。
  - **本地开发安装**（`file:` / `link:`）：若项目声明了 GitHub 仓库，自动比对本地与上游差异，清晰标明「本地领先」、「本地落后」或「与上游一致」。
- **状态细分与统计筛选**：状态筛选提供 `全部`、`有更新`、`已是最新`、`需关注`；安装来源（npm / GitHub / 本地）是另一个独立下拉筛选，因为本地检出同样可能落后上游。列表支持一键按状态或名称排序。
- **紧凑列表**：每行合并名称、状态与版本，介绍默认一行，安装 spec 与发行说明展开查看——一屏能看到更多插件（v0.7.0 起）。

### 2. 🔔 智能后台调度巡检与侧边栏实时气泡
- **灵活的后台巡检机制**：支持在设置中心自定义巡检频率（每 30 分钟 / 1 小时 / 2 小时 / 6 小时或自定义分钟数）。
- **非侵入式轻量提醒**：发现新版可更新（含 npm/GitHub 安装的 `update` 与本地安装落后的 `local-behind`）后，仅在左下角侧边栏底部显示低调的待更新数量角标（如 `↑ 插件更新 2`），绝不弹窗打扰当前对话与编码心流。
- **丰富的气泡操作**：
  - **版本迁移直观对比**：清晰展示每个待更新插件的 `当前安装版本 → 最新稳定版本`。
  - **忽略本次提醒**：本次暂不提醒，待检测到更高版本或手动点击检查时重新触发。
  - **全部忽略**：将当前所有待更新插件标记为已阅，跳过当前版本的持续提醒。
  - **状态持久化防丢失**：即便重启 DSH 桌面端或重载宿主，忽略列表与待更新状态完整保留。

### 3. 🤖 无缝联动智能体：「让 AI 更新」与「一键更新」
- **坚守只读安全底线**：插件自身**绝不静默运行任何安装脚本、绝不修改 `node_modules` 与配置文件**。
- **一键智能委托**：在气泡弹窗或插件列表点击「让 AI 更新」，插件会自动在当前会话输入框填入标准化提示词（例如 `帮我更新 billion-context 插件`）。未聚焦或无会话时自动回退为剪贴板复制，由 DSH 智能体遵循该插件的官方规范完成环境备份、版本更新与重启验证。
- **一键更新（批量）**：当检测到多个插件可更新时，气泡底部与设置页头部出现「一键更新」按钮。点击后**新建一个对话**，把整份更新清单填进它的输入框**但不发送**——清单含插件名、已装 → 最新版本、安装来源（`file:` / `link:` / `github:` / npm）与 profile 名，AI 据此逐个更新并回报结果。发送与否始终由你决定；新会话无法创建时回退当前输入框，再回退剪贴板。

### 4. 📖 深度 Release 变更日志解析（Changelog Diff）
- **区间化更新呈现**：自动抓取并聚合「当前安装版本 → 最新版本」之间的所有 Release 发行记录，不漏掉任何中间修复。
- **纯原生 Markdown 渲染**：内置自主实现的高性能轻量 Markdown AST 解析器（涵盖多级标题、列表、代码围栏、引用块、粗体与链接等）。
- **零 XSS 隐患**：纯字符串到 AST 再到安全 React 节点，全程不使用 `innerHTML`；链接额外做协议白名单，仅 `http(s):` 可成为可点击锚点（v0.4.0 起）。
- **按需惰性渲染**：默认保持折叠，展开单行时才解析渲染正文，即便长达数万字的更新日志也能瞬间展开，丝滑流畅。

### 5. ⚡ 工业级统一出站网络层与零配额浪费
- **单飞并发合并（Single-Flight Coalescing）**：同一时刻对相同 URL 的并发探测合并为单一网络请求（如多个插件引用同一上游仓库时共享一次请求）。
- **TTL 内存缓存 + ETag 条件请求（304 Not Modified）**：
  - 响应结果在 5 分钟内直接由内存返回；
  - 缓存过期后自动附带 `If-None-Match` 发起条件验证，**GitHub 304 响应完全不消耗匿名 API 配额**（60次/小时/IP）！
- **支持高额 API Token**：在宿主环境配置 `GITHUB_TOKEN` 或 `GH_TOKEN`，自动以 Bearer 头鉴权，配额提升至 5,000 次/小时。
- **全局并发限流与熔断保护**：出站并发上限严格控制为 6；若遭遇上游 403/429 限流，自动按 `x-ratelimit-reset` 进入静默冷却，并平滑降级至 jsDelivr CDN 保证可用性。
- **npm dist-tags 极速路径**：优先请求仅 ~200B 的轻量级 `dist-tags`，绝大多数已是最新版的插件一击即中，省去下载 MB 级完整 packument 的巨额带宽与时间。

### 6. 🛡️ 架构稳定性与原生设计融合
- **严格遵循 Cordis 4 生命周期**：清理逻辑全部通过 `ctx.effect` 挂载；调度器状态使用闭包隔离，杜绝向 `ctx` 挂载私有属性导致宿主崩溃的风险。
- **原子化落盘与 Profile 隔离**：状态写入采用临时文件（tmp）+ 重命名（rename）的原子操作；缓存按 Profile 严格分离存储，多 Profile 环境下绝不串台。
- **进程内串行写锁（withStateLock）**：彻底解决后台巡检落盘与用户前端操作（如点击忽略）之间的并发竞态问题。
- **深度融合 DSH Design Tokens**：经历 v0.3.2 配色全量重构，深色模式下按钮文字、高亮链接、卡片阴影与边框完全对齐官方无障碍标准。

## 🧭 状态含义一览

| 状态标识 | 界面展示 | 详细含义 |
|---|---|---|
| `update` | **有更新** | 上游存在比当前安装版本更新的正式稳定版，可展开查看多版本 Release 日志。 |
| `local-behind` | **本地 · 上游有新版** | 本地开发安装（`file:` / `link:`）声明的版本低于上游最新版；v0.4.0 起同样计入侧边栏角标提醒。 |
| `local-ahead` | **本地 · 领先上游** | 本地安装版本高于上游最新正式版（处于前沿开发中或上游发生版本回滚）。 |
| `local-latest` | **本地 · 与上游一致** | 本地安装版本与上游最新正式版完全吻合。 |
| `latest` | **已是最新** | npm 安装版本与上游最新稳定版一致。 |
| `branch` | **跟踪分支** | 安装来源为分支或特定 Commit（如 `#main`、commit sha），且已装版本号无法与 tag 排序；可排序时改判「有更新」或「已是最新」（v0.4.1 起）。 |
| `unknown` | **无法比较** | 引用形式无法识别出标准版本号（如非标准 tag）。 |
| `local` | **本地安装** | 本地安装且未声明上游 GitHub 仓库，无参考基准。 |
| `error` | **检查失败** | 查询上游失败（网络超时、域名无法解析或触发限流等），卡片内展示具体原因。 |

## 📦 安装与配置

> **前置要求**：已安装 DeepSeek Harness 且 Node.js 版本 ≥ 22。

### 方式一：推荐通过 Profile 安装（GitHub 远程源）

在终端中执行以下命令（以桌面版 Profile 为例）：

```bash
# 桌面版安装
dsh plugin --profile desktop add github:daha1216/dsh-update-checker

# Web 独立服务部署安装
dsh plugin --profile web add github:daha1216/dsh-update-checker
```

> 💡 **重要说明**：
> 1. 安装完成后，**请完全退出并重新启动 DSH 桌面端**（使宿主模块加载生效），然后**刷新一次 GUI 页面**（加载设置页脚本）。
> 2. 后续若要更新巡检器自身，重新运行上述相同的 `add` 命令即可。
>
> **兼容性**：`engines.dsh` 声明 `^0.2.0-rc.1`，即 **DSH 0.2.0-rc.1 及以上、0.3.0 之前**。装到不匹配的版本时，插件管理器会以 `incompatible-version` 明确拒绝；确实要在别的版本上试，可用 `dsh plugin allow-version` 加一次性豁免。DSH 升到 0.3.x 后需要本插件发新版放开范围。

### 方式二：本地开发安装（Checkout 模式）

如果你希望在本地克隆并进行调试修改：

```bash
git clone https://github.com/daha1216/dsh-update-checker.git "D:/dsh work/dsh-update-checker"
dsh plugin --profile desktop add "file:D:/dsh work/dsh-update-checker"
```

## 🏗️ 项目架构与技术细节

```
dsh-update-checker/
├── index.js          # Cordis 宿主插件核心：路由注册、RPC 通信、后台定时巡检调度器、生命周期管理
├── lib/
│   ├── http.js       # 统一出站网络层：单飞并发合并、TTL 缓存、ETag 304 条件复用、主机熔断与降级
│   ├── checker.js    # 纯函数检查逻辑：package.json 解析、多源版本探查、Release 聚合对比
│   ├── reminder.js   # 提醒状态管理：指纹计算、忽略策略、多 Profile 原子化落盘与并发串行写锁
│   └── md.js         # 零依赖轻量 Markdown 解析器：安全 AST 构建与 React 元素映射
├── client/
│   └── client.js     # 客户端设置中心与侧边栏渲染面板：双语国际化、UI 状态机、交互反馈
├── locale/           # 插件元信息多语言配置（zh.json / en.json）
├── assets/           # 实机界面展示资源
└── test/             # 详尽的自动化测试套件
```

### 1. 通信机制与安全栅栏
- 客户端设置页与侧边栏浮层通过 Connection RPC 通道（`/dsh-update-checker`）与宿主端通信。
- 宿主端将通道以 `kind: 'prefix'` 路由挂载至受信任的 `webServer` 上，逐分支遵循官方 `/api` 传输规范，并使用严格的同源与 Loopback 校验作为请求安全防护栏。

### 2. 调度器容错与并发保证
- 调度器完全闭包化，杜绝属性逃逸污染。定时器在纤维失效前即被 `ctx.effect` 严格清理。
- 运行中修改检查频率支持即时重排，任意时刻保证全局仅有一个活跃的巡检定时器。
- 扫描结果落盘与用户前台点击「忽略」通过 `withStateLock` 排队处理，杜绝数据覆写。

## 📝 更新日志

### v0.7.0（2026-10-26）
- **设置页改为「更新优先、设置收起」**：低频的后台设置不再占满首屏，插件列表的信息密度也不再被长介绍挤掉。四件事：
  - **后台提醒收成一条**：开关、当前状态与检查频率并排一行（`自动检查 · 已开启 · 每 2 小时`），频率选择器、说明与保存错误收进「设置」展开区。日常只看不改的人，一屏就能扫完。
  - **插件行瘦身**：名称、状态、版本合并进同一行，介绍默认只留一行（悬停有完整文本，展开可见全文），安装 spec 与发行说明移进展开区。同屏可看的插件明显变多。
  - **状态与来源分开筛**：安装来源（npm / GitHub / 本地）从状态 Chips 里拆出来，改为独立下拉框，只列出当前实际装了的来源。原先「本地」与「有更新」混在一排，读起来像互斥，而本地检出同样可能落后上游。
  - **按钮说人话**：「一键更新」下方常驻一行「新建对话并填入更新清单，由你发送」，不再只藏在悬停提示里。
- **本地落后行补上更新按钮**：`local-behind`（`file:` / `link:` 本地安装、上游有新版）此前会进「有更新」筛选与批量清单，却没有行内的「让 AI 更新」按钮。现在行内按钮与批量清单共用同一个 `isActionable` 判定，两类可更新行操作一致。
- **健康状态安静下来**：「已是最新」等正常状态从绿色改为中性色，红色只留给真正失败的行；一眼看过去，需要处理的才显眼。
- **测试**：`test/render-harness.mjs` 的状态种子随新增的 `sourceFilter` / `expanded` 更新，行内按钮断言改为锁定 `isActionable` 判定。

### v0.6.0（2026-10-26）
- **「一键更新」改为新建对话、只填不发**：此前点一下就把整份清单拼成提示词塞进当前会话并直接发送，等于替你按了发送键。现在改为**新建一个对话**、把清单填进它的输入框，**不发送**——发送时机由你决定。填的是新会话的输入框而不是当前那个，所以不会污染正在进行的对话；新会话的 composer 尚未挂载时，等它就绪再填（最长 10 秒），期间不会退而填到旧会话。新会话无法创建时回退到当前输入框，再回退剪贴板。
- **实现**：新增 `draftInNewSession`（订阅 `uiSession.adapter.current`，等主绑定切到新会话且其 `inputActions` 就绪后 `setDraft`），取代原先的 `sendComposerText`（`setDraft` + `submit`）；`batchUpdateHint` / `batchUpdateSent` 中英文案同步改为「新建对话并填好，由你发送」。
- **测试**：`test/batch-update.test.mjs` 重写为 43 项断言，新增「会新建会话」「草稿不落到旧会话」「新会话无 composer 时不乱填」「无 workspace 服务时回退当前输入框」「批量路径绝不调用 submit」等回归，并断言旧的 `sendComposerText` 已彻底移除。

### v0.5.0（2026-10-26）
- **一键更新（批量）**：检测到多个插件可更新时，侧边栏气泡底部与设置页头部出现「一键更新」按钮，把整份待更新清单整理成一条提示词交给 AI。
- **清单带安装来源**：每行含插件名、已装 → 最新版本、安装来源 spec（`file:` / `link:` / `github:` / npm 版本范围）与 profile 名——`file:` / `link:` 是本地检出，AI 必须去对应目录拉取而不是重新 `add`，缺了这条信息很容易空跑。
- **覆盖范围与角标一致**：`update`（npm / GitHub 安装）与 `local-behind`（本地安装但上游有新版）都算可更新。
- **测试**：新增 `test/batch-update.test.mjs`。

### v0.4.3（2026-10-25）
- **「立即检查」按钮现在每次点击都真的有反应**：此前点击后服务端在 90 秒新鲜窗口内直接返回缓存结果、客户端也不作区分，连续点击看起来完全没反应。现在手动点击会带 `force: true` 跳过新鲜窗口（仍在途扫描复用，不会重复烧 GitHub 配额），设置页的「检查更新」同样如此。
- **检查过程可见、按钮不会卡死**：检查中按钮显示已用秒数（`检查中… 3s`），并新增一行状态提示（`刚刚已检查` / `上次检查：5 分钟前`）；原实现里 `reload()` 抛错会跳过 `setBusy(false)`，按钮会永久停在禁用态——现改为一定会复位，并加了 90 秒看门狗兜底超时提示。
- **测试**：新增 `test/reminder-panel.test.mjs`（16 项源码守卫，锁定强制刷新、计时/看门狗、状态行与中英文案键），已接入 `npm test`。

### v0.4.1（2026-10-24）
- **未 pin 版本的 GitHub 安装不再漏报更新**：`github:owner/repo` 这类没有 `#ref` 的安装，此前只要上游存在 tag 就一律判为「跟踪分支」——即使已装版本明显落后（实测 dsh-retrace 0.4.55 对上游 v0.4.56 仍显示跟踪分支，既不算「有更新」也不进角标）。现在改为拿已装版本与最新 tag 比较：落后判「有更新」并带出版本区间，追平或领先判「已是最新」；只有已装版本号无法排序（如 `dev`、commit sha）时才保留「跟踪分支」。
- **测试**：新增三个夹具场景（无 ref 落后 → update、无 ref 追平 → latest、版本号不可排序 → branch），并修正分支引用的既有断言；integration 断言 21→24。

### v0.4.0（2026-10-24）
